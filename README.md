# Document Tracking System (Next.js + Supabase)

Same app as the wireframe/PHP version, rebuilt on the stack you asked for:
**Next.js on Vercel** for both the frontend and the backend (Server Actions
act as the API — no separate Express/Render server needed), with
**Supabase** (Postgres) as the database, auth, and file storage.

## 1. Create a Supabase project

1. Go to [supabase.com](https://supabase.com) -> New project.
2. Once it's ready, open **SQL Editor** -> New query, paste the contents of
   `supabase/schema.sql`, and run it. This creates all four tables
   (`departments`, `profiles`, `documents`, `document_logs`), the
   tracking-code generator function, locks every table down with Row Level
   Security, and creates the private `documents-files` storage bucket.
3. Go to **Project Settings -> API** and copy:
   - Project URL
   - `anon` `public` key
   - `service_role` key (click "reveal")

## 2. Configure environment variables

    cp .env.local.example .env.local

Paste in the three values from step 1.

## 3. Install dependencies and seed demo accounts

    npm install
    node scripts/seed.mjs

This creates two accounts directly in Supabase Auth plus their matching
`profiles` row:

- `admin@example.com` / `password123` (role: admin)
- `staff@example.com` / `password123` (role: staff)

## 4. Run it locally

    npm run dev

Visit `http://localhost:3000` — it redirects to `/login` automatically.

## 5. Deploy to Vercel

1. Push this project to a GitHub repo.
2. In Vercel, **Add New -> Project**, import the repo.
3. Under **Environment Variables**, add the same three values from your
   `.env.local` (`NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`,
   `SUPABASE_SERVICE_ROLE_KEY`).
4. Deploy. Vercel builds and hosts both the pages and the Server Actions —
   there's nothing separate to deploy to Render.

## How the pieces fit together

| Screen | Route | File |
|---|---|---|
| Login | `/login` | `app/login/page.tsx` |
| Dashboard | `/dashboard` | `app/(app)/dashboard/page.tsx` |
| Register | `/register` | `app/(app)/register/page.tsx` |
| Track | `/track` | `app/(app)/track/page.tsx` |
| Document detail / actions | `/document/[id]` | `app/(app)/document/[id]/page.tsx` |

- **Auth**: Supabase Auth handles sign-in; `profiles` stores the app-specific
  name/role/department for each account.
- **Data access**: all real queries go through `lib/documents.ts`, using the
  Supabase **service role** key on the server only. Row Level Security is
  enabled with no policies, so the public key (safe to ship to the browser)
  can't read or write anything even if it ever ended up in client code.
- **Tracking codes**: generated by a Postgres function
  (`generate_tracking_code()` in `supabase/schema.sql`) backed by a sequence,
  so two people registering documents at the same instant can't collide.
- **Files**: digital documents are uploaded to a private Supabase Storage
  bucket; the detail page requests a signed URL (valid 1 hour) to view them.
- **Audit trail**: every action (submit, approve, reject, forward, return)
  inserts a new row into `document_logs` — existing rows are never touched.

## Known limitations (things to extend later)

- No public sign-up screen — accounts are created via `scripts/seed.mjs` or
  the Supabase dashboard for now.
- No email notification when a document is forwarded to you.
- File uploads aren't restricted by type/size yet.
